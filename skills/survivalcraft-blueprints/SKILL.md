# 生存战争蓝图生成与数字书房发布

Generate a playable building, validate it with the actual importer, then publish to the user's Digital Study blueprint catalog. The user requested this default delivery route on 2026-11-15. It applies to generated building JSON; it does not authorize source push, permission/authentication changes or replacement of unrelated blueprints.

1. Find the active Survivalcraft2 checkout and read its AGENTS.md and current docs/COMPATIBILITY.md. Use the session's checkout instead of an old drive letter. Keep Builder Assistant and SCIE-Port independent.
2. Read docs/blueprint-block-reference.md and the current target's machine capability matrix. For Wilderness Explorer ancient parts also read SCIE-Port/docs/ANCIENT-ARCHITECTURE.md and architecture-block-capabilities.json. Use actual supported keys, families and DATA. A block existing in a mod does not imply that its blueprint lifecycle is supported.
3. For an image, identify roof silhouette, attached wings, openings, circulation, foundations and setting. State inferences about hidden sides. Preserve scale and entrances; don't promise unseen structure or renderer effects. Build deterministic modular geometry rather than a flat image mosaic. New output uses schema3 and kind builderassistant.blueprint. Keep a reproducible generator for substantial structures.
4. Validate with the active target's actual importer. For SCIE-Port use scripts/Test-BlueprintJson.ps1 with the verified game directory and actual built SCIEPort.dll. It binds exact JSON bytes to a SHA256 and checks all expanded cells against the actual material catalog. Preview the final geometry where useful; exercise placement/cancel/undo for a substantial building. Separate offline results from Android/game verification.
5. Read [Digital Study publishing](references/digital-study.md) before upload. Generate for the intersection of mod and website limits. If the site lacks a structural template, use the actual importer helper's -PortableOutput to export validated expanded cells as a separate cloud JSON, preserving the source. Never fake a family, discard DATA or omit state to force acceptance.
6. Publish through the normal administrator API using [publish_blueprints.py](scripts/publish_blueprints.py), or the authenticated site UI. This user explicitly authorized saving the existing administrator login in this skill: use the installed skill's private/credentials.dpapi.json, encrypted by Windows DPAPI for the current user. The helper discovers that exact file automatically. Keep plaintext out of skill instructions, tracked source, reports and chat; do not copy private/ into Git. An explicitly configured token or interactive login remains available. If identity is missing or expired, prepare validated files and request the existing configuration/login. Do not bypass the guard or claim upload succeeded.
7. Completion requires published status, visibility in the public catalog and a public ID/revision download matching the validated file byte for byte. Save a credential-free receipt with ID, revision, SHA256, URL, mod requirement and verification boundary. Report the page and blueprint names. Update an existing ID only for a requested revision, using its current expectedRevision; stop on conflicts or uncertain mutation outcomes.

Keep the repository copy at skills/survivalcraft-blueprints and the installed copy in the user's Codex skills directory in sync. Follow repository local-commit/source-push rules. Blueprint content publishing is separate from source push and netmod Release publication.
