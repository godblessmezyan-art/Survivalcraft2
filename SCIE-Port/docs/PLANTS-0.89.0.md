# 植物模型与果树生长 0.89.0

2026-11-16，用户要求优化已有植物建模，并为作物增加相应生长逻辑（包括苹果树）。全部在本地main、SCIEPort单工程中实现，版本统一0.89.0；Builder Assistant不变。没有引入外部模型、纹理或原生游戏源码，没有使用Blender导入资源。

## 模型

世界、手持与物品栏使用同一套原创程序化BlockMesh。使用闭合渐细茎、分枝、树皮纹路、带脊和厚度的折叶、分瓣花、立体果实；网格不越出其占用格，采用原生顺时针面序/Face光照与1×1白色Rgba8888纹理。单网格上限1800三角；非有限坐标、退化三角、索引越界及越格由构建检查拦截。纹理在Block.Initialize创建，正常阶段网格预热；CPU缓存加锁，避免区块线程与物品栏同时首次访问的竞态。

## 苹果树

苹果树物品放到耕地、泥土、草地的顶面后从DATA0开始。旧DATA0–15仍作为旧树苗解释，旧成熟结果苗仍保留原苹果与树苗掉落；没有批量迁移存档。树苗依照原低3位分阶段长大，阶段6或旧阶段7在合适轮询长成树。

生长需要上方光照≥10、季节温度加高度修正>2，冬季暂停。耕地水分和氮肥沿用原10/8/6轮询间隔，泥土/草地采用不额外加速的基数。轮询是原生扫描轮次，不能当作固定秒数。成熟时仅在耕地有氮肥的情况下扣1氮，不能重复扣。

成树占地包围盒3×3、5格高，实际21个方块：根1、上段树干2、树冠18。树冠下层为十字四臂、中层3×3、顶层十字五格。周围需要的20格全部已加载且为空才施工；建筑、水、其他植物、原树冠均不会被覆盖。空间不足、跨未加载区块、根高于250或越过整数/世界高度边界时保留树苗，后续轮询重试。

树冠春季开花，夏季逐渐形成青果，秋季继续成熟；推进还需要光照与温度，每4轮询最多一步。冬季即使黑暗也会清除花果状态，保留当年采后锁。生存模式通过原生挖掘采熟果，每冠2苹果并保留空树冠；当年秋季不能马上再刷果，下一春解锁。最多18冠/36苹果每完整树每年；无季节子系统的特殊世界采用连续分阶段再生。空冠可再挖掉；春季只补全仍有完整树干、已加载且为空的原冠位，不覆盖玩家改建。创造/爆炸等原生noDrop拆除按原生规则直接移除，不伪造果实。

拆根、挖断树干或失去地面支撑后，属于该根的残余部件由有预算轮询清理，不产果、不改其他树；未加载的根/区块先等待，不能误判为无根。不是即时全树砍倒/木材系统。

## DATA与存档边界

| 939 DATA位 | 含义 |
|---|---|
| 0–2 | 树苗生长阶段；树冠花果阶段0–7 |
| 3（8） | 成熟果位，沿用原位 |
| 4–5（mask48） | 0旧树苗、16根、32树干、48树冠 |
| 6–7 | 部件相对根X+1，仅0/1/2有效 |
| 8–9 | 部件相对根Z+1，仅0/1/2有效 |
| 10–12 | 部件相对根Y，1–4 |
| 13（8192） | 当年采后锁 |

根为16|7，不使用相对坐标。固定目标Terrain.MakeBlockValue/ReplaceData/ExtractData已经验证能正确保留所用0–16383数据和光照。旧世界并未测试；各端必须统一0.89.0，旧版本不认识这些结构位，禁止混版。

云莓915的低2位：0旧版/成熟果、1空枝、2花、3青果，夏季每3轮询前进，其他季节清为1。野莓903沿用bit0成熟，bits1–3记录再生进度，春夏每3轮询一步，四步结果；其他季节清花果进度。两者需要自然地面/耕地支撑、光照≥8、温度>2。原成熟云莓DATA0与野莓DATA1保持可读；干冷/遮阴不推进。

上述模组ID及结构DATA不属于蓝图材料；不得直接写入蓝图cells来创建树干/树冠。方块清单已同步，原81材料/10家具模板及Builder Assistant边界保持。

## 事务、更新线程与联机

固定目标SubsystemBlocksScanner.Update在游戏更新中调用OnPoll；不在区块生成线程改变地形。苹果子系统实现IUpdateable，在两次Update之间最多64次保留写入额度，施工前按2×计划数量预留正向与撤销，单计划最多24格；完整树含肥料最多22格。没有后台施工队列或跨帧半棵树，取消/根替换在提交前写0格；阻塞时后续轮询重试。

流程为生成固定计划、校验空气/区块/坐标、捕获全体写前签名、逐格校验与ChangeCell、读回确认。异常、原生领地/Hook拒绝或签名变化时按逆序有条件回滚；不覆盖中间出现的第三方替换。撤销写入失败或无法恢复原状态会记录错误，并停止该世界实例之后的苹果生长事务。光照从比较签名中剔除，正常异步光照重算不会误触发冲突。

年生作物、竹与两种莓果共用额外64次/引擎帧的写入上限。保持原单格耕作逻辑，没有无界扫描；蘑菇的已有原生轮询和禁用雨后生成的规则保持。

Local/Server推进生长，Client不主动改变地形。目标原生ChangeCell保留领地与Hook检查，服务器排队原生地形同步。采收使用已验证的DestroyCell→掉落物行为OnItemHarvested→单次ChangeCell：Apple子系统同时处理940掉落，野莓子系统同时处理904/916掉落，将原生替换值改为空枝。这样客户端与服务器得到同一个最终值，避免OnBlockRemoved里嵌套写入造成同步顺序颠倒。没有自定义包、附加握手或新玩家UI。
