# 第三方 Mod 移植规范与注意事项

本文件适用于 `SCIE-Port/` 内所有第三方 Mod → Survivalcraft NET
`Net_x25.01.17` 的移植。Builder Assistant 只做自动建筑、蓝图、批量建造与安全撤销，任何第三方 Mod 的代码或资产都不得迁入或打包进 Builder Assistant。

## 1. 来源与许可

1. 开始移植前记录上游名称、精确版本或提交、公开来源、取得许可的日期与授权范围。
2. 对进入发布包的每个上游资源记录 SHA-256；公开分发前归档权利人的许可原文。
3. 只迁入任务明确要求且获许可的范围。不得因某一资源获许可而推定整个 Mod、依赖或游戏内容都可分发。
4. 禁止提交或打包原 APK、游戏 DLL/PDB、内容包、上游 DLL/PDB 和来源不明的依赖。

## 2. 工程隔离

- 移植实现统一放在 `src/SCIEPort/Features/<来源或功能>/`。
- CSV、XDB、模型和贴图放入 `src/SCIEPort/Assets/` 的对应目录，并使用不会与其他来源混淆的文件名。
- 每个来源在 `THIRD-PARTY-NOTICES.md` 与 `docs/DEPENDENCIES.md` 单独记录。
- 不引用 Builder Assistant 源码或资产；两个工程独立版本、独立构建、独立产物、独立兼容性证据。

## 3. SCNET 重写要求

- `.scmod` 不能重命名为 `.netmod`；旧 DLL 不能直接复用。
- 所有类型、Hook、方法签名、数据库类名和内容加载路径必须针对 x25.01.17 实际程序集重新验证。
- 新增方块先反射扫描原版 `Block.Index`，再检查本工程全部常量；记录占用区间，并提示与其他 Mod 的外部冲突风险。
- XDB 中原版文件夹必须复用原版 GUID；模板 GUID、参数 GUID、成员 GUID 全局唯一，继承父级必须可解析。

## 4. 物品名称

- 创造栏/物品栏显示上游原名。
- 除非上游原名本身如此，禁止在名称后追加 `（移植）`、`（授权移植）`、`（预览）` 或任何同类括号标注。
- 授权、来源、完成度和“待验证”状态写在文档或物品说明中，不写进显示名。
- 对名称敏感的移植应在打包脚本中固定条目数与顺序哈希，并拒绝中英文括号。

## 5. 世界与存档安全

- 世界生成只处理当前生成区块，并设置明确的尝试次数和写入上限。
- 运行期补刷采用每帧/每次更新预算；禁止一次更新无界遍历全部已加载区块。
- 不在未知线程修改地形。联机行为必须分别说明 Local、Server、Client 权限；无证据时不得声称会同步。
- 首次运行只用有备份的可丢弃单人新世界，禁止直接测试玩家主存档。

## 6. 构建与交付门槛

每次发布至少完成：

1. `scripts/Test-Environment.ps1`：程序集哈希、API 与方块 ID 冲突检查。
2. Release/net472 编译，警告视为错误。
3. `scripts/Test-Database.ps1`：XDB 根、原版文件夹 GUID 与继承关系检查。
4. `.netmod` 内容检查：必需资源、CSV 类名唯一、显示名约束、模型结构和禁带二进制。
5. 更新 `docs/COMPATIBILITY.md` 与 `docs/TEST-RESULTS.md`，只使用“已确认 / 待验证 / 不支持”。
6. Android/7723 未实测的项目必须标为“待验证”，不能用 Windows 编译或静态检查替代。
