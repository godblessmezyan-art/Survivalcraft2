# Survivalcraft2 载具开发质量规范

## 一、总体目标

本项目开发的载具不是功能演示 Demo，而是准备长期使用的正式游戏内容。

任何新载具在首次正式交付时，都应尽最大合理努力达到完整、美观、协调、可用的质量标准。

禁止把"能运行""能加载""编译成功"视为开发任务完成。

## 二、模型设计标准

1. 在建模前明确参考车型、整体比例、结构和视觉风格。
2. 优先实现高质量低多边形模型，必须与 Survivalcraft 2.4 游戏美术风格协调。
3. 禁止用简单立方体堆砌替代完整的车身或机身设计，除非确有合理的造型需要。
4. 优先使用斜面、曲面近似、多边形轮廓、局部细节和分层几何结构改善外观。
5. 必须完成外部结构、内部空间和必要的机械细节。
6. 模型尺寸必须与玩家角色、座椅、碰撞体和游戏地形协调。
7. 车轮、螺旋桨、舱门等需要运动的部件，应在建模阶段设计独立的动画结构与旋转轴心。

## 三、贴图质量标准

1. 禁止仅使用默认纯色材质作为正式贴图。
2. 必须提供完整的配色方案、UV 映射和材质区分。
3. 根据载具类型，表现玻璃、金属、喷漆、橡胶、机械部件等不同材质。
4. 必须检查 UV 拉伸、接缝、贴图方向、纹理重复和透明度问题。
5. 模型与贴图应统一设计，不允许模型完成后随意附加一张临时贴图。
6. 贴图分辨率与材质数量应兼顾 Android 移动端性能。

## 四、人物与载具融合标准

1. 座位布局必须在模型设计阶段确定。
2. 必须为玩家身体、头部、腿部及手臂预留合理空间。
3. 必须核验座位挂点的局部坐标、旋转以及玩家实际渲染位置。
4. 优先支持真实坐姿，不允许把站立人物直接叠加在座舱内当作最终方案。
5. 驾驶员和乘客必须随载具稳定移动与转向。
6. 不得通过隐藏整个角色模型来掩盖穿模缺陷。
7. 无法通过现有 API 实现的坐姿或动画功能，必须明确说明技术限制，并尽量完成可行的替代方案。

## 五、开发与交付规范

1. 先审查真实源码、现有模型格式和可用渲染能力。
2. 在确认技术边界后，直接以完整高质量作品为目标进行开发。
3. 可以通过局部测试验证模型、动画、贴图等系统，但不得把测试用简陋模型作为最终交付。
4. 不允许为了尽快完成任务，擅自删除已经明确提出的视觉和功能需求。
5. 遇到复杂问题，应优先尝试合理的工程解决方案，不得未经分析直接宣布无法实现。
6. 保证游戏性能、Android 兼容性与联机稳定性。
7. 所有完成状态必须基于真实代码、资源和测试结果，不得虚构。
8. 如果资源制作能力或工具链确实不足，必须准确列出未完成内容、阻碍原因和可执行的下一步，而不是用低质量替代品宣称完成。

## 六、最终验收

完成一款载具意味着同时达到：

- 模型结构完整，外观协调且具有辨识度。
- 贴图细节完善，材质表现合理。
- 动态部件运转正确。
- 驾驶员与乘客乘坐位置自然，不明显穿模。
- 操控逻辑稳定。
- 联机状态同步可靠。
- 物品栏图标与游戏内外观正确。
- 未引入明显性能问题或严重兼容性问题。

编译成功仅代表通过技术检查，不代表项目完成。

**开发原则：高质量目标先行，技术验证贯穿过程，禁止以最小可运行版本代替最终作品。**
