# 神器开发前的 PixelFX 评估规范

2026-11-06用户要求：**以后开发神器，要先看看PixelFX可不可以用特效。**适用于本工程新神器、已有神器技能特效重做或升级；未涉及特效的纯修复不要求重新选型。
这是实现前的必要步骤，不是要求每个技能都强制使用PixelFX。仓库根及SCIE-Port的AGENTS.md都指向本文件。

## 先检查，再实现

1. 阅读[已接入实现](PIXELFX-V0.1.md)、[当前优化与边界](PIXELFX-OPTIMIZATION-0.77.1.md)及[固定效果目录](PIXELFX-CATALOG.md)，检索神器的元素/动作/技能阶段。
2. 先看已有三个可复用clip及预览。其它目录候选只有线索：从固定上游提交读取对应源码与meta/依赖，核对许可、人物mask、背景、源锚点、时长/循环、镜头/地面假设；实际离线导出预览后才能决定采用。
3. 在该神器的专项md写下评估结论（模板见下方），再修改表现代码。按蓄力、命中、爆发、持续状态和收尾分别评估，允许部分采用。
4. 适用时优先复用 `tools/pixelfx/export.mjs` 和 `Features/PixelFx/`，同类共用图集/批次。候选不适用时写具体原因，再采用原生几何/其它原创效果，不必为不采用PixelFX另行询问确认。

## 判断适用性

| 条件 | 决定依据 |
|---|---|
| 表现内容 | 电弧、火花、光晕、蓄力、命中爆发等可作为精灵叠层；名称相似不等于可直接适配。 |
| 立体与视角 | 任意方向长射线、连锁路径、武器运动轨迹、门户/护盾空间几何仍需真实3D；可以添加精灵，不能把平面贴图当作必要3D替代。 |
| 时间与锚点 | 源帧事件必须映射到既有技能时钟/位置，不能为了匹配动画延后伤害、增加前摇或更改冷却；人物/地面位置须验证。 |
| 资源与运行时 | 固定提交/许可/哈希；离线PNG+JSON+C#表；目标native解码/混合/采样/透明与纹理大小实际取证。运行端不带JS或联网导出。 |
| 手机性能 | 图集内存、存活实例、每相机quad/顶点/覆盖预算、采样帧率、距离/屏幕外剔除、减闪及退出释放均须有明确上限。单个新场景不能绕过全神器同时施放的总预算评估。 |
| 网络及身份 | 只订阅已有鉴权/去重后的表现事件。不因选用特效修改权限、伤害、冷却、存档、网络协议、物品ID/DATA/GUID。确有独立机制需求时另按任务授权与兼容规范处理。 |

持续循环特效不是当前一次性播放器的既有能力，新增循环须单独设计停止/所有者生命周期与预算；不能反复无界重发一次性效果模拟。
当前通用场景每实例为方形帧格、每场景一个图集，支持Screen/Vertical朝向；复杂倾斜平面/跟随武器骨骼等不是自动获得的能力。

## 记录模板（放入该神器专项md）

```markdown
## PixelFX选型

- 神器/技能及评估日期：
- 已检查的现有clip/候选ID（类别/名称）：
- 来源提交、源码/依赖/许可与哈希记录：
- 预览、角色mask/背景移除、视角/锚点/时间窗：
- 结论：采用 / 部分采用 / 不采用；具体原因：
- 保留的3D表现；与现有表现事件、去重及生命周期的接点：
- 图集内存、三档实例/quad/覆盖上限、减闪和多人同时施放预算：
- 自动测试与Release/包结果；Android/真实Local/Server/Client单列状态：
```

若决定不采用，只记录实际检查到的候选、约束和原因，不虚构已看源码或完成导出；若暂时缺来源证据，明确列为待验证，不将该资源放入交付包。

## 实现和交付

- 固定源代码/提交、完整许可及源码/资源SHA；不修改上游快照来隐藏差异。新增来源保存在SCIE-Port，禁止跨工程挪用Builder Assistant源码或资源。
- 导出器需能离线、固定种子复现PNG/JSON/C#帧表；新资源补帧范围/锚点/透明留边、native读入、编译表和包内一致性测试。
- 一次加载图集，复用池和纹理批次；不在Draw/每帧读取文件、解析JSON、创建Texture2D或无界分配。减闪、暂停、屏幕边缘、多人压力、退出/重进及设备恢复分别验证。
- 当前三档限制是现有雷锤精灵层的预算，不能让每件新神器各自叠加一份却声称全场景仍达标；专项须说明共享或合并预算策略。
- 自动测试、目标固定ABI、Release/包验证及文档一并提交；Android7723、触屏多分辨率与实际单人/主机/普通客户端单列验收，不能用Windows隔离代替。
- 技能图标仍遵守AGENTS.md的image_gen要求；PixelFX是场景特效来源，不是图标生成替代方案。持有移速+20%、近战攻速+10%、独立Tab和主题槽位规则保持。
- 默认仅本地main提交，由用户自行push。
