# 阿比斯军势升级 / 0.64.0

当前版本0.65.2已更新三种召唤物数值、用战马移速10替换170%规则，并增加生命列；见[现行军势说明](ABYSS-ARMY-0.65.2.md)。下文保留0.64版本历史。

> 0.65.0新增第三种召唤「地狱三头犬·刻尔柏洛斯」，每位主人唯一；旧军势功能与七只上限保持，见[三头犬说明](ABYSS-CERBERUS.md)。骑乘为下一阶段，本版仅原战马可骑。

## 0.64.1：军势面板与无响应修复

用户安卓截图确认旧版背景右/下边界与内部按钮失配，下方次位面按钮溢出；同时报告召唤、收纳等无反应。只读反编译固定目标的Widget.Measure/Arrange、CanvasWidget和DialogsManager发现：Widget.Arrange不会把ActualSize除以LayoutTransform缩放，而Canvas仍按固定坐标布置子控件。旧版只缩放面板会使边界与内部尺寸失配，不能继续沿用此布局。

新版在Dialog.MeasureOverride取得实际父区域，统一缩放面板尺寸、内部坐标、控件尺寸与字体，保持LayoutTransform=Identity，留出四周边距并使用原生ClampToBounds。召唤类型、七行军势、召唤/召回/解除、收回次位面/召回现世均纳入同一重排。

管理命令原本复用了禁止骑乘/身体挂接的战斗Actor，并会无提示返回false；新版为召唤、同步、召回、解除、收纳及现身单独校验，仍要求本人存活、持有武器和主机认证，但允许骑乘状态提交。涉及有乘客坐骑的移除/收纳/强制归队继续拒绝，提示先下马。仅战斗技能保留原动作/骑乘限制。管理命令不依赖正的GameTimeDelta，并使用实际时间限流，避免菜单暂停后限流不结束。没有真实会话日志，不能把骑乘判定称为用户“无响应”的唯一已确认原因。

命令提交立即显示正在处理或等待房主；本地前置拒绝、队列满、服务器动作锁及召唤冷却均有反馈。召唤按钮直接显示剩余秒数，仍为30秒冷却。解除只有请求成功提交才清掉选择。网络252与保存v2布局保持，无新资源或方块变化。

使用：先切换死亡权柄，打开左侧军势面板，点顶部「召唤类型」切到夜魇战马，再点「召唤」。在冷却结束、有安全空地且未达到七只/世界24只上限时由主机创建；失败原因会显示在面板。

回退分支 `backup/abyss-0.64.0-before-dialog-fix`，0.64.0旧包保留。沿用下文用户要求，只编译并用 `Build-ManualTestCandidate.ps1` 打包，不执行测试套件、GPU或游戏。Android布局、触摸/骑乘操作和房主/客户端处理均待用户验收；同房所有人需0.64.1。

本轮依用户要求只编译和打包，**没有运行自动化、GPU、游戏或联机测试**。用户负责实玩验收。0.63.0的177项原生/198项GPU历史结果不适用于本轮新增行为。

## 当前规则

- 每人最多七只契约生物，包含转化、冥界猎犬、夜魇战马及收纳在次位面的生物。世界24只总预算保持；隐藏不释放名额。
- 面板按钮统一为「召唤」，上方可切换类型「冥界猎犬／夜魇战马」。取消“已有一只猎犬”限制，允许重复召唤，仍保留30秒召唤冷却。七行列表显示现世、次位面和待加载记录。
- 夜魇战马使用游戏原生 `Horse_Black_Saddled`，自带鞍和 `ComponentMount`；原生狼仍引用 `Wolf_Gray`。没有打包游戏模型或新增生物物品ID。所有同版玩家可按原生骑乘操作上马。
- 战马行走/骑行速度为其原生速度的170%（1.7倍，额外70%），不是额外170%。房主和骑乘客户端分别归还本功能上次的增量，再按当前基数重算，不反复累乘；随契约恢复重新应用。其他属性和原生坐骑档位不变。
- 无乘客时战马作为契约生物跟随/护卫；有乘客时停止军势寻路，保留原生 `ComponentSteedBehavior` 控制，其他自主行为保持停用，避免抢方向。乘客下马前拒绝收纳、解除或强制归队。
- 死亡蔓延仍为半径24、高差16格、CD36秒。1.25秒扩散完成时，所有者全部存活契约生物回满生命，不受24格距离限制；已死亡生物不复活。次位面及待加载契约记录标记为满血归来。敌对生物仍由主机按128候选/帧去重结算，所有玩家、友军、玩家承载体和领地保护保持。
- 解除任何契约均让生物直接消失，不恢复野生。需要二次点按确认；次位面记录直接删除，现世实体走原生RemoveEntity/Dispose而不是致死/掉落路径。尚未加载的记录保留指纹删除标记，目标实际加载后延迟到Update移除，避免原生Add/Remove网络事件交错；至多128条待删除记录，超过时拒绝继续解除并反馈。

## 次位面

「收回次位面」保存原生实体组件快照，然后从主机世界正式移除实体并释放实例。世界里不存在该生物的AI、碰撞或渲染；通过原生实体删除消息让其他玩家同步看见消失。不是仅降低透明度或把生物移到远处。

「召回现世」从快照重建，保留模板、生命和原生可保存的组件状态；在玩家附近已加载、未被领地保护、不与方块/移动结构/生物碰撞的空地放置。使用新的世界实体ID并保留独立契约键；空地不足或恢复失败则继续保留次位面记录，可再次点击。已骑乘/有附属身体的实体暂不收纳，避免连带移除玩家。尚未加载的旧契约需等实体载入后才能收纳。

契约键与世界实体ID分离，避免生物隐藏后世界复用其旧ID，导致其他生物被误认为友军。252保持原字节布局，增加收纳/现身动作9/10及友军行的隐藏/待加载/战马标记，使用Caster携带当前世界实体ID。旧0.63客户端不理解新语义，联机各方须统一0.64.0。

保存仍用独立 `DeathAuthorityV1` 子键，内部版本升为2；读取旧版本1并迁移。新增稳定契约键、次位面原生快照和待删除/回满血标记；旧星门、方块952/DATA、数据库GUID及249/250布局保持。未知或损坏数据保留原样并关闭死亡操作。回退0.63时不支持新版军势操作，原数据保留，须重新升级才能取回次位面生物；测试前保留世界备份。

原生API只读核实：`Project.SaveEntities`、`EntityDataList.Save(ValuesDictionary)`及其构造函数，`Entity(Project,ValuesDictionary)`、`publicLoadEntity`、`IdToEntityMap`、Add/Remove事件同步。目标ProjectNet的LoadEntities对Id=0不会执行组件Load，因此恢复显式加载组件、自引用临时映射后清零ID，再AddEntity分配新ID。没有使用虚构次位面或实体克隆API。

## 重击修正

虚空与未赋能的死亡形态：长按松开均走原断界斩（25格飞行斩及4秒残隙，原100初击+60残隙），不再回落为原52点近身重斩。手机Hold独立维持按住状态，不因某帧没有Dig/Hit/Aim射线而提前松手；必要时用原生角色眼方向补射线。缺失本地开始采样时补发开始/释放。房主收到未配对但更新的释放消息时，从房主时间开始补足蓄力，不立即伤害；保留动作锁、Token、序号、防重放、范围/遮挡与领地/玩家保护。247字节布局保持，6/7/8既有动作类型保持。

赋能12秒期间仍只允许普攻，不释放重击，HUD明确提示禁用。此轮仅做源码修正与编译，不能据此声称用户遇到的真机重击问题已实测解决。
