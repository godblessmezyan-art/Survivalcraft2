# 0.80.1 普通玩家神器、星门与骨龙同步修复

用户报告：加入房间的玩家在神器图谱点击“解放真名”无反应，无法使用阿比斯星门；骨龙只有加入者无法起飞，房主正常。

## 原因与目标取证

固定 Windows Net_x25.01.17 的原生 `ClientPackage.Handle(SyncList)` 把最初解包的 `From` 存入 `NetNode.Server`，随后把列表中另一份 ID=0 的 `Client` 加入 `NetNode.Clients`，两者共享同一个 `NetPeer`。`NetNode.AddClient` 只更新字典，不替换 `Server`。之后 `PackageManager.DecodePackages` 从字典按实际连接查找发送者，写入 `IPackage.From`。

因此合法主机包的 `From` 与 `node.Server` 并非同一对象，TokenId 也可能不同。原移植的对象身份判断丢弃254真名快照、250星门列表/传送回执、252死亡权柄/军势/飞行状态；251空间技能与247断界斩的二次队列检查也存在同类问题。图谱在主机可能已解放，但加入者收不到状态，继续认为神器封印；骨龙移动属于骑手客户端，却收不到主机飞行模式。

取证来自本机实际程序集反编译，且新增测试调用了原生 `ClientPackage` 压缩流往返与 `Handle`，并非自行模拟“两个对象应相等”。忽略目录 `artifacts/multiplayer-abi/` 保存只读取证。目标指纹：

|---|---|
| Survivalcraft.exe，2.4.0.0 | `3D14B8D698546F13E66FBF49DBCFAC45A2CDDFC97709D738050DF2E1CC74A7AD` |
| Engine.dll | `98F2035B98129259567E39ECAC46638226B46A842D3062D83AA934716E770694` |
| EntitySystem.dll | `7A87E6435DBC81652D610D26934BBD7594314C3D4A7DD7C765DF4F5BB67ED19C` |
| LiteNetLib.dll，1.0.0.0 | `D9C49444639102021EC6141C66E61B35F57493D3393CF2A737F68195C362D25A` |

## 修改范围

`Compatibility.ServerConnection` 以原生登记的主机对象作为接收来源：仅在字典 ID=0 对象与 `Server` 共用同一非空 `NetPeer` 时解决上述对象差异。接收方仍要求 `From` 就是这份登记对象；仅伪造相同 ID、GUID、TokenId、Peer 的另一对象不会通过。会话标识使用登记对象的 TokenId，处理排队包时再次验证来源和入队时的 TokenId。

真名、星门、死亡权柄、空间技能、断界斩统一使用这个解析。座位238的主机消息入口也使用同一解析，避免同一个入房差异阻止坐姿同步。真名副本在换会话时清空旧掩码/修订号，等待新主机快照；主机世界中的 `TrueNames` 保存记录不变。

新增的 LiteNetLib 是游戏目录只读引用，`Private=false`，环境检查器核验其指纹和 `Client.Peer`/`TokenId`/`NetNode.Clients` ABI，包内不携带游戏网络库。仍为 net472/API1.42/SC2.4.10.6；加载器、Hook、协议编号及字节布局、物品ID/DATA、GUID、存档键与资源不变。神器基础移速/攻速/专属物品栏背景不变；不修改技能伤害、召唤概率、星门共享权限或骨龙物理算法。

## 验证与实机复测

旧0.80.0 DLL负对照在真名回执、星门完整快照和死亡权柄世界握手三个新断言上分别失败；修复DLL通过。新增骨龙检查把真实自定义移动组件绑定至原生骑乘身体，经过真实包入口和更新队列接收主机起飞/降落状态，并拒绝重连前排队的起飞消息。这是组件隔离检查，没有运行飞行物理或手机游戏。

构建、包指纹和各检查数量见 [测试结果](TEST-RESULTS.md)。本机 ABI/Release/隔离回归属于 **已确认**；Android7723、触屏/多分辨率及真实 Local/Server/Client 为 **待验证**。没有取得本次7723 APK/程序集指纹，不能把Windows结论自动推广到渠道重打包。

同房各端统一安装0.80.1并完全退出重启，移除旧版本包，保存原存档备份。首先在可丢弃测试世界执行：

1. 房主和加入者分别使用图谱，加入者解放任意一件神器，确认只有自己的选中项变化且换手可用；保存、退出重进后检查进度。
2. 两端共享星门列表；加入者建立、改名、选择目的地并走入门，验证到达和原生移动恢复，重复一次重连后的传送。
3. 加入者骑自己的骨龙，起飞、上升、悬停、下降、降落；房主观察位置同步；房主也骑自己的骨龙复测。
4. 加入者退出重连，确认图谱/星门/军势重新同步，旧回执不会改变新会话。

这些步骤在真实设备完成前均保持 **待验证**，不把包检查、旧版负对照或本机组件检查写成实机兼容。
