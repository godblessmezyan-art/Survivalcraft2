# 双人折叠山地庇护帐

在建造与家居找到折叠帐篷。生存配方在工作台用四份竹材放四角、四份亚麻纤维放边上、火把放中央。手持并点击有可见顶面的坚实地面，前门朝向搭建者。地面顶面中心被遮挡时，露出的一角也能通过验证。被点击的地块可以支撑任一前角。

展开占地 2×2，两扇帐门通向同一个帐内空间，两张睡垫并排铺在与帐布同色的地布上。两路出口均需要可站立地面。底面与支撑之间允许一格落差，低处会展开短支脚。进入后点地上的睡垫，按脚下位置使用对应铺位，满足睡眠条件时两门自动关闭。点正面门柱可手动开关该门，点任一后壁灯具可开关同一盏暖灯。睡眠期间帐外玩家无法打开两门，帐内玩家开门时会唤醒睡着的玩家。全员离开后点帐外篷顶收回，背包满时物品掉在脚边。

帐布、地布和收纳包采用深蓝配色，内饰有银蓝窗轨、缝线睡垫、通风格栅、内壁置物台和灯具状态灯。帐内抬头点后半部天窗，在深蓝遮光和透明玻璃之间切换。左右侧墙第二格各有一扇带窗帘的观景窗，点侧窗独立开合窗帘。

## 技术约定

- 方块 947/DATA0 是折叠物品。地形部件为 `1 + (part << 4) + rotation + (state ? 4 : 0) + (lit ? 8 : 0)`。0–3 为底面，4–7 为中层，8–11 为篷顶，12–15 为可选支脚。朝向 0–3。状态位在 0、1、4、5 表示闭门，在 6、7 表示窗帘拉开，在 10、11 表示天窗透明。旧帐篷自动使用默认遮光状态。原版方块表、本仓库已编译各 Block.Index 检查通过。同装其他模组仍需避免编号碰撞。
- 请求包 233 用于指定原生目标格、预期值和操作类型。预期值中的光照位承载命中面编号，主机按目标侧窗或后灯的实际表面重新射线验证。在更新线程复核玩家、地形、领地和库存。先记录原值，后逐格写入和广播。每批最多十六格，失败回退本次已经写入且仍归帐篷的值。部分结构遭破坏时唤醒使用者并清理剩余部件。主动收帐成功后返还一件。
- 1.13.1 使用原生互动射线定位支撑面。主机最多复核顶面五个采样点，并依次检查两个前角对应的占地。客户端若刚换槽，先提交原生选槽，再提交开帐请求。主机通过请求处理远端操作一次。手持折叠帐点击已展开的帐体会进入原生互动。
- 门、窗、灯和朝向随原生地形值保存同步。天窗两格作为同一事务切换，左右窗帘独立。玻璃使用原生透明批次，保留碰撞和点击表面。原生区块光照以左后壁为唯一光源，关闭为 0，打开为 12，左右灯具控制同一光源。
- 睡眠检查完整帐体、脚下地布高度、占用、浸水与湿身。开启生存机制的非创造模式检查疲劳。两个帐门按同一事务闭合，成功后调用原生 `ComponentSleep.Sleep(true)`。原生睡眠包 23 处理入睡与唤醒。全世界的睡眠加速和醒后复活点按原版规则计算。
- 两门闭合时按实时地形和玩家位置判定整个帐内的保护，清醒和睡眠都适用。只在动物来源已识别时拦截命中、伤害、击退及硬直。状态变化记录在方块 DATA，保护在客户端按已同步地形用于本地反馈。
- 第一人称折叠帐采用独立的 0.30 倍手持比例和右下偏移。帐布略内缩避免与岩壁共面，地形绘制保留帐布的完整三角面。
