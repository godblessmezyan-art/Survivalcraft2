# 双人快艇技术审计与实机验收

日期：2026-10-20  
目标：Survivalcraft NET 2.4 `Net_x25.01.17`，Android 7723，`net472`  
范围：只修改 SCIE-Port 水上载具；不修改 Builder Assistant、坦克、铁路或植物。

## 实现结论

现有 `SCIEPortSteamBoat` 已升级为双人快艇，继续使用物品 ID 999、实体名
`SCIEPortSteamBoat` 和实体 GUID `6c6a3db4-8a2f-4616-b345-6c17e127e812`。
授权 SCIE 模型与贴图继续使用，源文件不被覆盖；包内 Y_UP 派生模型只增加了底面归零。

船体规划以模型真实边界为依据，而不是凭视觉放大：

| 项目 | 数值（格） |
|---|---:|
| 模型 X / Y / Z 边界 | -1.058..1.058 / 0..1.694 / -2.353..2.743 |
| ComponentBody | 2.3 × 1.75 × 5.6 |
| 驾驶位 | (-0.42, 1.0, -0.45) |
| 乘客位 | (0.42, 1.0, -0.45) |
| 座位中心间距 | 0.84 |
| 右侧下船点 | (1.65, 0.5, 0) |

该尺寸给模型四周留有小量碰撞余量，避免视觉船体伸出碰撞箱；两个座位仍位于船体内，
0.84 格横向间隔能容纳约 0.6 格宽的玩家碰撞体。下船点位于 1.15 格半船宽之外，且没有
超过原生近距离上船搜索的合理范围。

## 真实 API 审计

- `ComponentMountPackage` 只定位实体，不携带座位编号；同一实体复制两个原生 Mount 无法稳定寻址。
- 原生 `ComponentPlayer.Update` 在骑乘带 `ComponentBoat` 的实体时，会让每名骑手都向同一
  `MoveOrder`/`TurnOrder` 写输入。双人直接共乘会造成乘客覆盖驾驶员输入。
- 因此快艇不再挂原生 `ComponentBoat`。`ComponentSteamBoatDrive` 只读取
  `ComponentTwoSeatManager.Driver` 的输入，并复现已审计的转向、推进、限速和受损下沉规则。
- `ComponentBody` 仍负责浮力、水阻、空气阻力、碰撞、重力和原生实体保存，未用逐帧传送模拟物理。
- 两名玩家都是船体的直接子 Body；座位偏移只在分配/恢复时写入，乘客观察方向不会写入船体转向。
- 服务端通过自定义离散座位包 ID 240 下发驾驶员/乘客角色；普通客户端不能自行分配座位或修改船速。

## 座位与生命周期规则

1. 第一名上船者分配驾驶位，第二名分配乘客位，第三名触发原生下船流程。
2. 只有驾驶员输入参与前进、倒车和转向；乘客输入不参与车体控制。
3. 下车、死亡、断线或父子 Body 关系解除时，座位管理器从当前直接子 Body 重建占用。
4. 临时玩家网络 ID 不写入世界存档；重载后依据原生保存的父体和座位偏移恢复角色，避免幽灵乘员。
5. 船严重进水时驾驶员与乘客均触发下船。

## 联机边界

已实现的权威路径是单机以及 Server 主机本地玩家驾驶。普通客户端作为乘客时，只接收服务端的
离散座位结果并依赖原生父 Body 同步跟随。普通客户端作为驾驶员仍为“不支持”：目标运行时现有
父车 BodyUpdate 路径不能替代完整的服务器驾驶输入、预测和纠偏协议，不能通过客户端直接改船速
或其他玩家位置来掩盖该缺口。

## 自动检查

- 水上载具规则测试覆盖模型边界、座位间距、上下船位置、水面推进门控、加速度、限速和三人分配。
- 打包脚本检查快艇必须有且仅有一个原生 Mount、必须有共享双座管理器、不得含原生 Boat。
- XDB 固定检查座位、下船和 2.3×1.75×5.6 碰撞体。
- DAE 固定检查 Y_UP、`Cylinder` 节点、98 顶点、模型边界以及目标 Engine 的 1 bone/1 mesh 导入结果。

## Android 7723 验收清单

请仅在新建的可丢弃世界和备份后测试，并先删除旧 `SCIEPort` 包：

1. 冷启动游戏，确认 Mod 列表显示 0.11.0，进入世界无数据库或资源错误。
2. 创造栏找到“SCIE 双人快艇”，检查图标、手持和世界模型不黑、不空白、不竖直、不沉地。
3. 在浅水和深水各放置一艘，检查尺寸约 2.3 格宽、5.6 格长，碰撞边界贴合船体。
4. 第一名玩家上船应位于左侧驾驶位；前进、倒车、转向和停车正常。
5. 第二名玩家上船应位于右侧乘客位；其移动/观察输入不得改变船速或方向。
6. 第三名玩家尝试上船应被拒绝；两名乘员分别下船后应能重新按顺序占座。
7. 驾驶中检查乘客无明显抖动、穿船或与船体碰撞弹飞；两人均可安全从右侧下船。
8. 分别测试驾驶员死亡、乘客死亡、客户端断线、船沉没，确认座位释放且无幽灵乘员。
9. 空船和双人船分别保存退出并重进，确认位置、朝向和实体存在；不应恢复已离线玩家占座。
10. 分别记录单机、Android 主机和普通客户端结果。普通客户端驾驶员不是本版本验收目标。
