# 0.86.1：睡眠射线安全、恒温床与壁炉取暖

2026-11-16：拉取 `origin/main`，起点 `55e77f0`，已是最新。用户报告床在单人、联机房主均闪退；书架来自其它设备制作，用户要求无法定位时不处理，本次没有改动原版家具或外部设计数据。

## 睡眠根因与修复范围

固定 Windows Net_x25.01.17 的 `ComponentSleep.CanSleep` 通过九条非交互射线检查上方遮蔽。`Block.Raycast` 即使没有命中，也无条件读取 `array[nearestBoxIndex]`（初值0）。原模组窗帘962、窗帘上部963返回长度0的碰撞数组；悬浮陈列器954及非法969/970 DATA也存在此返回。射线经过这些格子就可抛出 `IndexOutOfRangeException`，不局限于联机。

新增本工程 `BlockRaycastSafety.NonSolid`：返回一个零体积盒，避免目标 ABI 的空数组越界。窗帘本体、窗帘上部及悬浮陈列器显式保持不可碰撞；合法床/餐桌占位的真实碰撞和所有交互盒保持。有效碰撞几何无变化，不写玩家存档或地形，不改床复活点/睡眠规则。

床请求增加死亡/离开世界/组件失效/已睡眠/座位或骑乘状态检查。仍走原生 `CanSleep`、`Sleep(true)`、原生23睡眠包；不绕过湿身、疲劳和遮蔽。异常保留完整日志并以短反馈中止当前请求，避免直接冒出到游戏更新循环。

该原生越界已在固定目标程序集隔离夹具复现；尚未取得用户手机堆栈，因此不能断言它是手机报告的唯一原因。

## 壁炉

只修正964模型中的火舌、火芯、余烬三类源网格：UV采样现有图集的中性浅色区域，外焰/余烬红橙、火芯橙黄，并使用原生顶点自发光。固定Engine导入器把所有网格名替换成根节点名，因此使用哈希固定的On模型导入顺序19–33，不依赖丢失的名字；回归逐项比对源几何与实际Engine导入包围盒及材质范围。保留石材外壳、炉台、其它家具图集及全部DAE/PNG字节。没有新粒子、透明层、闪烁或额外更新开销。

bit2点燃时 `GetHeat=1`（原0.35），熄灭为0；光照仍8/0。原生温度系统的局部热源项为 `36*heat`，旧0.35仅为12.6；提高到1提供更明确的取暖。辐射、距离、遮挡、衣物与环境继续由原生温度系统处理，不直接改玩家体温。

## 用户追加：床自带保温

本轮用户明确要求“床增加特性：自带保温，无论温度多少都能睡着”。966/970床范围内已进入原生睡眠的玩家，体温维持原生舒适值12（原生体温范围0–24）；进入睡眠立即生效，四格/四朝向均支持。床不再因极寒/过热导致睡眠中温度伤害或温度昏厥。湿身、疲劳、遮蔽、死亡等原生入睡条件保持；原生CanSleep本就不额外检查温度。

Home子系统Load注册一个仅本世界存活的IUpdateable，使用实际目标Input=-10，先于原生Default=0生命状态更新；现有SubsystemUpdate回调在每个原生子步结束后再校正。包括睡眠加速的每个子步，不只每渲染帧。复用既有OnCreatureInjure，只拦截原生ComponentVitalStats的25/26/35三种低温/过热原因，要求无攻击者且未ignoreInvulnerability；不免疫攻击、火焰、岩浆、溺水等其它伤害。

不改变衣物保温、湿度、环境温度缓存或世界温度；醒来、移离床范围、床被拆除、死亡或退出世界立即不再提供保温，后续按原生环境换热。不恢复睡前危险体温，也不恢复旧温度昏厥。普通客户端仅维护本人视觉/体温，主机维护权威玩家，不改远端玩家；继续使用原生生命状态同步，不增协议或存档键。Dispose注销提前更新器。
