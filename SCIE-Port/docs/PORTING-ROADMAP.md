# SCIE-Port 分阶段路线图

原则：每个阶段都独立可加载、可关闭、可回滚；先单人，后联机。任何阶段只有通过对应证据门槛后才能标为“已确认”。

## Phase 0：基线与加载探针（本次）

交付：独立 net472 工程、SCNET loader、modinfo、环境检查、打包检查、创造栏测试材料、上游固定工具和审计文档。

验收：

- Release 0 warning / 0 error。
- 包仅含自己的 DLL、modinfo 和 Assets。
- 在 Windows x25.01.17 新建单人世界加载，并在创造栏找到 `SCIE Port Test Alloy`。
- Android 目标包重复加载与创造栏检查。

当前只完成前两项；运行验收仍待验证。

## Phase 1：稳定材料注册（推荐下一阶段）

这是下一步最合适的模块，因为它依赖最少，又能建立后续所有配方、机器、化学和交通所需的稳定标识体系。

范围：

1. 建立 `ContentIdRegistry`，记录旧 ID/data、新 ID/data、稳定字符串键和引入版本。
2. 先 clean-room 实现 3–5 种基础材料（例如测试铁粉/钢锭语义），不使用未授权 SCIE 美术。
3. 每个变体用稳定枚举值，禁止依赖数组插入顺序。
4. 添加纯 .NET 单元测试：编码往返、非法 data、防越界、旧值映射。
5. 在 Windows 与 Android 创造栏验证显示、堆叠、丢弃、拾取、保存和重载。

## Phase 2：配方与第一台无电机器

先移植一个闭环：输入材料 → 机器库存 → 分帧处理 → 输出材料。建议选结构最简单的压板/粉碎类机器，而不是熔炉、电路或交通工具。

验收包括放置/拆除实体、库存保存恢复、处理中退出重进、区块卸载重载、异常配方、满输出槽、取消和错误日志。不得替换原版 crafting/furnace/player 组件。

## Phase 3：矿物与世界生成

实现新的矿物块和受预算限制的生成 Hook。只在新建可丢弃世界测试；先关闭旧世界改写。定义世界 seed 下的确定性与版本升级策略，并验证不覆盖已生成区块或原生重要结构。

## Phase 4：化学领域核心

先把 `Atom`、`Compound`、`DispersionSystem`、`Equation` 作为不依赖游戏进程的库独立重写和测试，再接入材料与反应机器。禁止把化学数组位置作为永久存档 ID。

## Phase 5：电路

先单线程、主线程分帧实现拓扑和基本电源/导线/负载；加入区块加载边界、循环图、断线重连和预算测试。之后才能评估后台纯计算。Jint 脚本为可选后续子阶段，默认关闭并限制执行时间、宿主 API 与存档大小。

## Phase 6：交通工具

按“生成实体 → 无乘员物理 → 单人骑乘 → 燃料/损坏 → 保存恢复”顺序实现。船、飞艇、火车分别建模块，不复用 `ComponentNPlayer`。输入从目标玩家/骑乘扩展接口读取。

当前 0.5.1 已建立蒸汽船、飞艇、火车和车厢的单人预览探针：独立物品、独立实体、原生骑乘、
本地触屏驾驶输入和有限加速已经通过编译及打包。游戏内生成、骑乘、保存恢复仍待验证；
原蒸汽船模型/纹理与飞艇模型已按用户声明的许可接入；燃料/热量、发动机库存和多人权威同步尚未实现。

0.5.1 已迁移 `RailBlock` 的直轨、弯轨、坡轨方向编码和邻接更新，并实现机车/车厢仅在轨道上生成及沿轨导向；飞艇和火车模型已统一为 Y_UP。
为便于实机验证，车厢当前可独立低速试乘；自动编组、父子实体存档、货箱、脱轨/断联处理必须在基础轨道运行证据通过后实现。

## Phase 7：多人权威同步

为每个模块列明权威方：

- 材料/库存/机器：主机或服务端确认变更，客户端只请求并显示。
- 电路：服务端模拟或按确定性 tick 同步快照；客户端不得直接写地形/库存。
- 车辆：服务端权威实体、驾驶者输入序列、乘员座位状态和周期纠偏。

测试矩阵必须分开记录单人、主机、普通客户端；还要覆盖加入中游戏、断线、重连、驾驶者死亡、区块卸载、不同延迟和 Mod 版本不一致。

## 发布门槛

- 获得可公开分发的 SCIE 内容授权，或确保所有实现与资源均为 clean-room/自有许可。
- 固定 Android 7723 包的程序集指纹并重跑 ABI 检查。
- 每个阶段都有 Release 构建、包清单、Windows 运行、Android 实测记录；涉及联网时另有主机/客户端证据。
- 不发布旧 DLL，不重打包游戏本体，不在包内附带游戏资源。
