# 家具互动 / 0.80.0

2026-11-08，基于本地 main 的 0.79.0 家居开发。用户要求“做家具互动”，并沿用“无需验证、由用户亲自测试”的指令。本轮只执行 Release 编译和增量打包，没有运行 Test-Environment、自动测试、游戏、手机或真实联机。**编译已确认，实际运行待验证**。实际命令及产物指纹见 [构建记录](TEST-RESULTS.md)。

## 玩家操作

| 家具 | 本版交互 |
|---|---|
| 单人、左座、中座、右座、转角沙发（960） | 使用后坐下，每个模块一个座位；移动、跳跃或“起身”离座 |
| 双人餐桌（965，隐藏部分969） | 使用桌椅任意占位，优先靠近的一张椅子；两张椅子分别占用，可两人同时坐下 |
| 壁炉（964） | 既有开关同时控制仿焰、原生热量和方块照明；关闭后热量和发光归零 |
| 冰箱、橱柜、床头柜 | 保留原储物/开门入口与8格可存入规则，历史后8槽只取；不改原版容器 |
| 水槽、窗帘 | 保留水流外观开关、开合状态 |
| 双人床 | 保留站在床上请求原生睡眠、原生条件检查及唤醒，不新增复活点或床位独占 |
| 茶几、挂画 | 保留装饰用途，本版不增加面板或动作 |

界面仅增加短按钮“起身”，使用原生触屏控件和现有 ArtifactSkillHud 安全排布，避让原生操作控件；空间不足时隐藏。移动/跳跃仍可发起离座。没有常驻教程、机制数值或概率说明。水槽水流仍是外观，不提供饮水或灌溉；餐桌没有新增进食系统。

## 坐姿与生命周期

- 复用现有 SubsystemHomeFurniture，并接入真实目标的 `OnModelAnimate(ComponentCreatureModel, out bool)`。坐姿只作用于正在占座的 ComponentHumanModel，设置身体、头部、手臂和双腿变换，保留原生基础透明度/受伤颜色。相机高度通过原生 EyePosition 缓存调整，不修改模型资源。
- 座位脚点按根坐标、现有四朝向和沙发款式计算。餐桌左右椅分别面向桌心；未被占用的另一椅可作为候选。坐姿期间角色身体横截面临时收窄至不大于0.42格，高度保留原值，以避开实际椅背与桌沿；视觉身体按身高比例下移，原生物理更新后将本机/主机身体位置约束到座位脚点。家具本身的碰撞不改。
- 仅保存本会话的原碰撞尺寸。退出时只在尺寸仍等于本功能应用值的情况下恢复，避免覆盖其它Mod的调整。不修改 WalkSpeed、攻速、重力、ParentBody、骑乘组件或实体模板，不创建锚点实体、GUID、存档键或持久化坐姿。
- 坐下要求角色存活、可操作、无睡眠/骑乘/父体/浸水/飞行/梯子状态，且不处于蹲伏；只接受人形模型。主机检查根值、合法DATA、有效区块、3格内距离、可见性、领地、空闲座位和碰撞空间。每个候选空间最多检查96格，并检查附近实体。
- 离座优先寻找邻近有地面支撑且能容纳原尺寸的地点，餐桌/沙发顶部及原进入点作为有界后备。普通离座找不到位置时保留座位并提示“周围没有空位”。家具被拆、受伤、状态冲突或租约过期会释放；仍在座位附近且存活时尝试安全落点，不把已经远离的玩家拉回家具。强制释放且无安全落点时恢复原尺寸、不改地形、不强行瞬移，后续交给原生碰撞处理。
- 世界退出释放尺寸与GUI引用；读档不恢复坐姿，角色位置和正常物理继续由原生存档处理。没有修改已存储物品、物品槽或旧家居状态。

## 主机与协议

新增独立 `HomeSeatingPackage` **238**，不改239的17字节布局、action0/1或其它既有包。只读元数据读取本机目标39个原生IPackage的ID常量，原生未占238且无无法识别的getter；源码搜索只有新家居包声明238。这不覆盖其它已安装Mod或7723重打包程序集。

238固定未压缩38字节：Kind(byte)、Actor(ushort)、Revision(uint)、Root(3×int)、Expected(int)、Seat(byte)、Active(bool)、MoveOnExit(bool)、Exit(3×float)。Kind0坐下、1起身、2主机状态、3请求快照、4租约、5拒绝。客户端不能通过Kind2/5向主机写状态，接收状态仅信任原生Server连接；主机将From绑定真实PlayerData/EntityId，客户端不能指定其它Actor。拒绝非有限坐标，所有世界操作排队在更新线程执行。

请求队列上限128、每次更新处理8条、活动座位上限64。坐下/起身本机节流0.25秒，主机请求节流0.2秒；序号使用uint回绕比较，并绑定认证连接及ComponentPlayer会话，重连复用EntityId时重新起算。主机每0.5秒复查家具和空间，每1.25秒发布活动状态；客户端每1秒续约、每3秒请求快照，租约5秒。序号/限速会话最多128条，满时只清理已移除角色，不无限增长。正常玩家无需手动批准。真实网络顺序、晚加入和丢包恢复尚未测试。

联机各端统一 **0.80.0**；与0.79及更早版混装不支持。内部SCIEPort身份、旧Block ID/DATA/GUID/存档键和原生存储协议保持。家具是普通家居，不属于神器，不添加神器属性或槽位主题。

## 壁炉

使用既有DATA bit2作为开关，`GetHeat(value)` 开启返回0.35、关闭返回0；交给原生 SubsystemMetersBlockBehavior/玩家温度系统计算，不直接加减玩家体温。`GetEmittedLightAmount(value)` 开启8、关闭0，沿用原生方块光照传播，无额外光源实体、PBR、着色器或玻璃透明渲染。

继续使用原HomeFireplace/HomeFireplaceOn模型、图集与239主机开关入口，不添加燃料、烹饪、火伤或烟雾。0.35是原生热量参数，不是固定体温增量；实际效果受距离、环境和遮蔽影响。原生方块光照为亮度，不能保证冰蓝染色；冰蓝外观仍由仿焰几何和图集提供。
