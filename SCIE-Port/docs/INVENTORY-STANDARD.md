# 移植工程物品展示规范（0.44.0 起强制）

适用于全部现有物品及以后新增内容；Builder Assistant 不受此规范影响。

## 独立原生 Tab

使用 x25.01.17 的 `Block.GetCategory(value)`、`BlocksManager.AddCategory`、
`LanguageControl.loadJson`。原生创造面板按内部键精确筛选，中文标签只负责显示，
不创建自定义物品栏窗口或修改原生触屏布局。

| Tab 标签 | 内部分类键 | 当前内容 |
|---|---|---|
| 神器 | SCIEPort.Artifacts | 雷神之锤·伪、妙尔尼尔、昆古尼尔、全知之眼、吞噬之眼、波塞冬、阿比斯·终焉之镰 |
| 载具 | SCIEPort.Vehicles | 坦克、直升机、摩托、越野车、快艇、飞艇、火车、车厢、炮弹 |
| 圣兽套装 | SCIEPort.Saints | 万里青龙、北冥玄武、镇狱白虎、炽焰朱雀 |
| 生态植物 | SCIEPort.Plants | 作物、植物、种子等 |
| 食材 | SCIEPort.Food | 可食用果实、玉米棒、黄豆等 |
| 工业材料 | SCIEPort.Materials | 亚麻纤维、测试合金 |
| 工业部件 | SCIEPort.Industry | 齿轮、车轮、模具、活塞、钢瓶 |
| 建筑装置 | SCIEPort.Building | 竹材、铁轨、便携堡垒及其内部构件 |
| 生物生成 | SCIEPort.Creatures | 狐狸、兔子、鸡生成器 |

内部隐藏构件仍保持 `DefaultCreativeData=-1`，不会因为改 Tab 暴露到创造栏。
Tab 键隔离不等于 Block ID、ClothingData 或网络 ID 隔离：其它模组占号仍需独立审计，
不能用新增 Tab 或背景宣称外部模组编号冲突已经解决。
表内部分内容有多个 DATA 变体，分类一致；不改任何显示名、配方名、ID、DATA 或存档值。
默认顺序为上表次序，位于原版分类之后。`SCIEPort.Misc`“移植杂项”仅为运行时安全兜底，
不主动创建空 Tab，正式构建必须拒绝未明确分类或使用杂项的物品。

圣兽装备仍使用原版衣物块 203，仅 DATA 内的衣物索引 200–203 进入套装 Tab。
损耗/颜色不改变分类；其余普通衣服仍在 Clothes/Dyed。禁止把整个衣物块一起迁走。
所有新增分类必须同步修改 `PortInventoryRules` 的键/标签、CSV、文档与验证脚本。
以后新增神器必须归入神器 Tab，新增载具和专用弹药归入载具 Tab；不要为单件物品乱建 Tab。

## 槽位背景与主题

通过原生 `InventorySlotWidget.CenterColor/BevelColor` 提供主题底色与边框，
不增加覆盖物品图标的图片 Widget，不抢占拖放、长按、多点触控或数量文字。

- 妙尔尼尔：蓝紫雷霆；昆古尼尔：原有黑曜石/古金配色。
- 波塞冬：海蓝/金；全知之眼：深蓝/古金；伪锤：低饱和铁灰/古铜。
- 青龙：青玉绿；玄武：深海冰蓝；白虎：银灰/浅金；朱雀：赤焰红/暖金。
- main 0.47.0 的吞噬之眼 ID 950 使用紫黑/古铜主题；阿比斯 ID 952 使用深紫金属/浅紫边框专属主题。

所有神器必须有背景。新神器运行时有通用兜底，正式发布却必须注册专属 Theme，
测试拒绝 None/通用主题，不能把兜底说成专属美术已经完成。
默认属性（2026-10-30 用户要求）：新神器在用户未特别标注例外时，还必须同时具备持有移速 +20% 与近战攻速 +10%
（口径见仓库根 `AGENTS.md`）。专属背景与这两项属性合称“神器三件套”，缺任一项不得标记完成。
纯配色/轻微脉动，不依赖新贴图、透明混合或专属 shader。
复用历史 `MjolnirDisplay` 入口作为统一管理器，约 0.12 秒扫描；跨神器换装沿用同一份
原槽位颜色快照，不覆盖基线。普通物品/空槽、关闭面板/移除 Widget、世界退出或更换 Project
都恢复并释放原引用。四件套装按衣物索引识别，不能给所有普通衣服染上背景。

## 新增内容的强制流程

1. 审计 Block ID/衣物 DATA/网络 ID，分类展示不能替代编号避冲突。
2. 所有 CSV `DefaultCategory` 必须为允许的 `SCIEPort.*` 键；每个新增可注册 Block 必须有 CSV。
3. 若按 DATA 分组，覆盖真实 `GetCategory` 并验证所有创造值与带损耗/颜色变体。
4. 神器/特殊套装在 `PortInventoryRules.Select/Colors` 注册主题并添加规则测试。
5. 跑 `Test-PortInventory.ps1`（构建前 CSV/命名，构建后真实 Block getter/翻译/幂等分类/槽位 ABI）
   与 `SCIEPort.Inventory.Tests`，保留伤害、模型等既有检查，不能删除断言来绕过展示规范。
6. 按 `PACKAGING-RULES.md` 产出 `荒野探险家.netmod` 与同字节版本副本。

## Android 7723 验收（待验证）

在备份后的可丢弃新世界冷启动安装新包；记录渠道包哈希/版本、设备与分辨率。
安装目录只保留同一模组的一份新包：不要同时安装旧 SCIEPort.netmod、中文主包和版本副本，
文件名变化不改变内部 PackageName，重复安装仍会重复注册/冲突。
打开原生分类选择列表，检查九个独立 Tab 及全部分页，原版分类无本工程物品混入，
原生“全部”等汇总视图按其原有语义保留。正常原版衣物仍能查看、穿戴、染色。
在创造栏、快捷栏、背包、箱子与穿戴槽查看背景；四件套装配色不同，全部神器有背景，
图标、数量、选中态可读；多次将神器/套装换成普通物品/空槽，无残色或 Widget 叠加。
测试左右手、不同 UI 比例、关闭/重开背包、存读档和换世界，以及房主/客户端各自本地 UI。
离线 API/规则通过不代表上述渲染、触控与多人 UI 已通过实机验收。
