# SCIE-Port 坦克 v0.2 审计

日期：2026-10-20  
分支：`codex/tank-v0.2`  
目标：Survivalcraft NET `Net_x25.01.17`，Android 7723，单人模式优先。

## 本轮确认的问题

1. 旧 `T34Tank.dae` 只有车体、炮塔、炮管三个长方体，贴图是近似空白的单像素资源，无法表现履带、负重轮和部件层次。
2. `TankBlock.Initialize` 对每个网格同时提交正常和反向绕序三角形，物品栏面数无必要地翻倍。
3. `ComponentTankDrive` 在自行计算滑行减速的同时保持 `ComponentBody.IsGroundDragEnabled = true`，会叠加原生地面阻力。
4. 离地时旧控制器主动把水平速度向零插值，导致短暂腾空立即失去惯性。
5. 旧碰撞盒 `2.4,1.1,3.4` 不能覆盖炮管；座位与下车偏移也与重建后的模型不匹配。

以上 1、2、3、4 为源码直接证据；碰撞盒结论由模型坐标包围范围与 XDB 参数对照得到。实际 Android 视觉和驾驶手感仍需实机验证。

## v0.2 实现

- 保持方块 ID `924`、实体模板 `SCIEPortT34Tank`、数据库 GUID 和 `TurretYaw`/`GunPitch` 存档字段不变。
- 用 `scripts/New-TankAssets.ps1` 生成项目自有、可重复构建的 Y_UP 模型和贴图。
- 模型包含 20 个独立低多边形网格，导入层级固定为 `TankHull > TankTurret > TankGun`，目标 Engine 实际导入结果为 3 骨骼/20 网格。
- 64×8 RGBA 贴图包含 8 种完全不透明的装甲、履带、轮胎和金属色；世界模型使用接近白色的漫反射乘数，避免绿色贴图再次乘绿色而过暗。
- 物品栏遍历全部网格，只提交正常绕序面，不再重复反面。
- 驾驶员存在时关闭原生地面阻力，由坦克控制器统一处理推进、倒车、反向制动、松油滑行和侧滑抑制；无人驾驶时恢复原生地面阻力。
- 推进只允许 `StandingOnValue` 地形接触；站在其他实体上、离地或浸水时不施加推进。离地时保留水平惯性，重力、空气阻力和碰撞仍由原生 `ComponentBody` 处理。
- 碰撞盒改为 `2.6,1.55,4.4`，覆盖当前炮管最大前伸范围；平滑爬升仍限制为 0.3 格。
- 每 5 秒输出一次低频驾驶诊断日志，不逐帧刷屏。

## 已验证

- `Test-Environment.ps1`：目标程序集版本、net472、Loader ABI、方块 ID 与载具所需 Body/Mount/Spawn 接口检查通过。
- 纯规则测试：推进、倒车、滑行、反向制动、限速、转向方向、转向缩放和推进许可共通过。
- 目标 `Engine.Media.ModelData.Load`：实际导入 3 骨骼、20 网格，低于默认 7 骨骼预算。
- Release 编译：0 warning、0 error。
- XDB 合并结构和 `.netmod` 必需资源检查通过。

## 待验证或不支持

- Windows 游戏内生成、骑乘、碰撞、保存重载：待验证。
- Android 7723 模型显示、触屏驾驶、第三人称视角和保存重载：待验证。
- 多人同步：不支持；自定义驱动仍只在 `WorkType.Local` 执行。
- 炮塔旋转、炮管俯仰、开火、弹药、爆炸与伤害：尚未实现。角度字段和模型层级仅提供第二阶段基础。
- 当前使用单一长方体 `ComponentBody`，不等同于履带/炮管的复合碰撞体；狭窄道路和墙角行为必须由实机测试确认。

## Android 验收顺序

1. 备份并新建可丢弃的单人创造世界，只安装本轮 `SCIEPort.netmod`。
2. 在物品栏找到 T-34 坦克，检查图标、手持模型、八色贴图和网格是否完整。
3. 在平地生成，检查方向、离地高度、炮管朝向和能否靠近座位上车。
4. 验证前进、倒车、松油滑行、反向制动、原地/低速转向及高速转向稳定性。
5. 验证 0.3 格小坎、完整一格障碍、墙角、窄路、坡面、悬崖和浅水；不得穿墙、穿地或在空中继续获得推进。
6. 下车后确认坦克自然停稳；保存退出再进入，确认实体位置、车体方向和模型正常恢复。
7. 若失败，保留首次 Warning/Error、完整日志、设备和 7723 客户端版本信息。

## v0.3 实机反馈与修正（2026-10-20）

用户确认 v0.2 坦克基础测试通过，同时确认三个缺陷：不能开炮、不能跨越完整一格、车体占地偏小。因此基础模型显示、生成、骑乘和驾驶标记为 Android 已确认；开炮、完整一格越障和尺寸满意度不能继承该结论。

v0.3 修改：

- 模型所有坐标整体放大 35%，Body 同步改为 `3.6,2.1,5.9`；座位为 `0,1.72,0.2`，下车偏移为 `2.25,0.4,0`。
- `MaxSmoothRiseHeight` 从 0.3 改为 1.05，复用原生连续 smooth-rise；没有瞬移、穿墙或改写地形。
- Android 攻击/命中触屏动作（`PlayerInput.Hit`）发射原版可见枪弹；弹速 42、冷却 1.6 秒，深水中禁止发射。
- 炮塔跟随水平瞄准角，炮管俯仰限制为约 -11.5° 到 +20°；角度仍写入原有存档字段。
- 炮弹命中并被原版弹体系统移除后产生压力 18 的非燃烧爆炸；仅施加水平后坐，避免向上后坐导致车辆异常飞行。

新功能已通过目标程序集编译、ABI 守卫、规则测试和包校验，但 Android 开火按钮映射、炮塔方向、命中爆炸、一格越障及放大比例仍待实机确认。爆炸会破坏方块，首次测试必须使用可丢弃世界。

## v0.3.1 Android 炮塔与自爆修复（2026-10-20）

Android 实测确认 v0.3 炮塔不会随视角转向，第一次开炮会炸到坦克。目标程序集反编译给出了自爆的直接证据：`SubsystemProjectiles.FireProjectileNet` 在 owner 非空时，会从炮口前方反向检测 owner 的玩家包围盒并重写弹丸起点。玩家作为骑手位于坦克内部，因此这段适用于手持武器的校正会把车外炮口重新拉回坦克碰撞箱。

v0.3.1 修正如下：

- 炮塔持续跟随 `player.GameWidget.ActiveCamera.ViewDirection`；触屏点击开火当帧优先采用 `PlayerInput.Hit` 射线。
- 发射方向根据已限制的 `TurretYaw`/`GunPitch` 和车体矩阵重建，与视觉炮管方向保持一致。
- 以 `ComponentBody.BoundingBox` 做射线/包围盒出口计算，炮口位于出口外额外 0.75 格。
- 创建弹丸时传空 owner，防止原生手持武器校正改写炮口；创建成功后立即恢复 `Projectile.Owner` 用于伤害归属。
- 炮弹至少飞行 1.5 格后才解锁爆炸；近车体停止的炮弹不会引爆。

原生重定位机制、源码修改、规则测试、Release 编译和包校验为已确认；Android 上炮塔是否可见转动、第一炮是否安全以及命中爆炸是否正常仍待实机复测。

## v0.12.1 点击自爆二次修复（2026-10-20）

Android 继续反馈点击开炮时坦克会自爆，证明 v0.3.1 的 1.5 格引信不足。该条件只比较炮弹当前位置与炮口起点；弹速为 42 格/秒，低帧率或较长物理步中可一次跨过 1.5 格，随后在仍能覆盖坦克的近地面或近墙位置触发压力 18 爆炸。

v0.12.1 保留既有 AABB 外炮口与空 owner 创建路径，并新增独立爆炸安全包络：

- 爆炸中心先按 `AddExplosion` 实际使用的整数格取整，再以格中心计算，避免弹丸浮点位置安全但取整后的爆点回到车旁。
- 爆点到坦克**当前** `ComponentBody.BoundingBox` 的最近距离必须至少为 8 格；在包络内即使炮弹已飞过 1.5 格也只消失、不爆炸。
- 仍保留 1.5 格最小飞行距离作为第一道引信条件；两个条件必须同时满足。
- 新增纯规则断言覆盖：车旁已解锁弹不爆、远处未解锁弹不爆、8 格边界允许爆炸、点到 AABB 最近距离计算。

本轮纯规则测试、`D:\SC` 固定 x25.01.17 程序集环境检查、net472 Release 编译、XDB/资源守卫和 `.netmod` 重打包均已通过；包 SHA-256 为 `228E3DFC3F15439C97023794684161423F3DC4336F231942A6F43B9825C4D63F`。Android 第一炮、贴墙/近地点击、8 格外命中仍为待验证，不得标记兼容。
