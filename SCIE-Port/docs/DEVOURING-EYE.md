# 吞噬之眼 / Eye of Oblivion V1

分支 `port/scnet-x25.01.17`，SCIE-Port 0.15.0；这是独立神器，不依赖 Builder Assistant。
创造栏“神器”获取，ID 950，无耐久、不可放置、近战/三种挖掘能力均为 0。
UpdateInput 将本物品的 Hit/Dig 触屏输入转入 Interact 确认流程，清除普通攻击/挖掘/瞄准，
避免长按绕过确认直接挖掉方块或攻击实体。切换其它物品不改变其输入。
原创黑曜石封印、古铜圆环、紫色晶体，独立 DAE/PNG，1 bone / 27 meshes / 816 triangles，
Y_UP、变换烘焙、128×16 全不透明调色板。只用常规贴图绘制，不用透明/发光着色器。

## 可玩的 V1 范围

六格内瞄准后点击使用，显示目标名称、类型、位置/DATA 或实体模板、距离及拒绝原因。
默认回收模式，必须再点击“确认回收并保存”；“识别·只读”关闭修改按钮。
确认只消费一次，操作结果留在面板，重新操作需关闭后再次识别。关闭/返回/外部关闭
对话框取消尚未开始的任务；玩家重生/离开、退出世界时释放旧界面与队列。

识别对地形、Body 与 MovingBlocks 同时射线，取最近命中后才判断合法性。
玩家以外的任何前景 Body（含未知、拒绝目标）都遮挡后方地形；移动方块结构也遮挡。
不会为了寻找“可回收”目标穿过玩家、未知实体、墙或家具。仅排除施术者自己的 Body。

### EntityRecovery

V1 唯一注册项为精确模板 `SCIEPortT34Tank`，GUID
`54904f9f-93bc-4e54-9a7d-4e0a8d3e4d5a`，返还 `TankBlock`（924）。
`AutoDespawn=False` 只作持久化状态复核，绝不是许可依据。必须同时满足：

- 目标仍在本 Project，模板名/GUID 均匹配，且只含本分支五种已验证组件；
- 没有玩家组件、容器或未知附加组件，没有父 Body、子 Body、Mount.Rider、其它 Rider 引用；
- 不处于 despawn、没有待重生记录或 owned-entity 依赖；
- 停稳（速度平方 <0.25）、射击冷却结束、已发射炮弹均已结束；
- 整个 Body AABB 列范围均在允许边界内、无领地保护处，背包有可用空间。

永久移除使用 `Project.RemoveEntity(entity,false)`，先保留内存实体供异常回滚。
不使用伤害、死亡、Despawn 或掉落路径。提交存档成功后才 Dispose 已移除实体。
快照保存完整 EntityData（含本分支炮塔/炮管角度）；部署物品不携带该姿态，重新部署
使用模板默认姿态。快照是异常人工恢复证据，V1 没有把实体姿态编码到部署物品。

### BlockRecovery

V1 只有下列明确的 1:1 回收映射（还需通过行为、邻域和权限检查）：

| 原生类型 | 有效 DATA / 保留规则 |
|---|---|
| Granite/Cobblestone/Planks/Sandstone/Marble/Basalt/Bricks/ClayBlock | 0 或 1+2×颜色编号（0–15） |
| Oak/Birch/Spruce/Mimosa/PoplarWoodBlock | 0、1、2，保留原木轴方向 |
| DirtBlock、GlassBlock | 仅 0 |

要求实际类型来自目标原生程序集；Mod 派生类、非法 DATA、不在表内的方块拒绝。
准确返还原方块值，仅剔除瞬时 Light 位，不调用普通挖掘掉落转换来丢失颜色或方向。
任何目标方块实体、交互/可编辑方块、非批准的 OnBlockRemoved 行为拒绝。
普通方块检查半径 1 的 26 个邻居；原木检查半径 3 的 342 个邻居，防止树叶衰败。
邻域有容器、行为、流体、沙砾、家具、门、植物或未知方块时保守拒绝，防止支持物移除、
连锁更新、掉落或结构损坏。区块未就绪或邻域跨出 0–255 高度也拒绝。
仅调用 `SubsystemTerrain.ChangeCell`，遵守其领地/TerrainChangeCell Hook，验证源格为空及
邻域值未变才返还；不调用 DestroyCell，不生成 Pickable，不修改邻格。

## 权限、背包与限制

V1 只允许 Local 主玩家，或 Server 本地具有 ServerManager/ServerMaster 的主玩家。
普通客户端只识别，不发送自定义执行请求，不自行删除/发物；远程玩家即使是管理员
也不通过此 V1 UI 执行。其它本地玩家、Adventure、无可验证本地存档时拒绝。
V1 不假定旧坦克有所有者字段；仅单机世界主玩家/服务器本地管理员具有全局处置许可。

原生所有领地保护区域一律拒绝，包括本人区域；世界安全范围为 X/Z 绝对值 <1,000,000、
Y 1–254（避免边界层），坦克按 AABB 全范围检查。第三方保护系统没有统一可验证接口，
需要另做适配，不宣称通用保护兼容。未识别 Mod 实体、狗屋/家具和关键实体始终不在映射内。

只接受已验证的原生 ComponentInventory / ComponentCreativeInventory，未知背包派生类拒绝。
生存背包检查可堆叠容量，返还一件并核对数量；创造背包只使用 OpenSlotsCount 内真正空的
可见槽位，不覆盖已有槽，不把虚拟目录当作储物空间。原生创造背包显示无限数量，V1 是
放入一个部署物品条目，不声称创造模式有精确的一件计数。满背包始终不落地、不删除源。

## 事务、持久化与恢复证据

主线程 GuiUpdate 每次最多一个目标，Project 级 single-flight、0.5 秒冷却；无批量功能。
确认后重新检查位置、射线遮挡、源身份、权限、乘客、映射、容量，并按顺序执行：

1. 世界目录 `DevouringEyeJournal/<事务ID>.pending` 写入原实体完整 JSON / 原格及邻域值、
   玩家 GUID、槽位原值/数量和返还值。只使用 SubsystemGameInfo.DirectoryName，无硬编码存档路径。
2. 原生 `GameManager.SaveProject(true,true)` 写入 before 检查点；读取 Project.json，用原生
   ValuesDictionary 解析并核对本子系统 LastCommittedRecovery 字段，不能只相信 void 返回。
3. 再次检查目标/背包/乘客；单源删除并验证；AddNetSlotItems 返还、验证后 OnSlotChange 同步。
4. 再次同步原生保存，核对结构化事务回执；ProjectNet 还核对该 EntityId 是否确实不在磁盘
   Entities 中。原生 Terrain.Save 保存修改区块，Project.Save 同时保存实体和玩家背包。
5. 日志改名 `.done`，移除的实体才 Dispose。失败先撤回新增物品，再恢复保留的实体或原格，
   验证后保存并改名 `.rolledback`。恢复中不覆盖已被外部改动的背包或占用格。

任何无法确认的回滚都会锁定后续回收，保留快照/日志；重进发现 `.pending` 也锁定。
V1 不会自动重放“发放物品”、猜测是否已发放或自动删除旧实体，避免崩溃后重复补偿。
日志最多 256 条，达上限后拒绝，需先备份归档。日志包含动态玩家 GUID，不应随安装包发布。

**边界**：原生区块文件与 Project.json 不是一个跨文件原子数据库事务。正常保存确认的
删除/返还有明确持久化链路；进程强杀、磁盘故障或用户恢复旧备份可能需要人工根据日志
恢复。V1 提供可恢复快照及锁定，不提供 V1.2 自动撤销/恢复 UI，也不宣称断电精确一次事务。
需要处理 pending 时：先停止修改并备份完整世界与日志，检查原对象、玩家背包和快照的一致性；
只有明确恢复到一致状态后才能归档 pending，再重进解除锁定。不要直接删除未知 pending 来重试。
