# Builder Assistant v0.23.0：一室一厅自动室内布局

日期：2026-10-30。SCNET x25.01.17 / net472。按用户安排，本轮不启动游戏、不进行Android真机操作；旧版本与本版本的设备验收继续标记待验证。

## 功能和范围

904工作台增加“一室一厅（自动家具）”，宽9..21、长13..25、固定单层、墙高4..6。支持木板/石砖外墙、四坡/人字/平顶、窗户密度和完整有符号整数种子。恢复默认和随机种子继续可用，旧的参数循环接口也使用该模板的合法范围。

复用原有Foundation/Wall/Openings/Roof生成外壳，以种子选择客厅/卧室分界及家具左右镜像。外墙只有一个原版入口门，内隔墙留两格高门洞和上方横梁。客厅与卧室各至少5排室内净深。床头朝向后墙；家具左右镜像时朝向/包围盒一起处理。

客厅放阅读桌、木椅、长椅和灯架；卧室放床榻、木柜和高书架，共7件。使用既有结构块模板，保留自然木色。床榻、柜子和灯架仅是现有装饰造型，不新增睡眠、储物或照明交互。未新增材料、族标签、DATA、模板ID、原生微体素家具、网络包或游戏Hook。

新增“交给903蓝图工具（保存/预览）”：重新应用参数，拒绝过期生成结果，通过现有材料校验后更新当前内存蓝图；不自动写磁盘。切换903可命名保存、删除/载入、旋转升降预览并确认施工。交接包含904选择的朝向，903初始旋转为0，避免重复旋转。904原有直接选择位置和确认建造路径继续可用。

## 通行和质量检查

- 先复用现有BuildingValidator检查外壳、入口支撑、墙环、空心体积和整体结构连通。
- 旧的单平面连通检查会把门洞上方横梁误判成堵路。仅新模板改为从脚部层检查外壳空间，随后独立执行更严格的两格高通行验证；其他模板判据不变。
- 家具经现有FurniturePlacementResolver展开，严格拒绝包围盒和结构/其他家具重叠，含原生门上半格。
- HomeCirculationValidator读取实际组合后的方块和家具配置，把整个家具包围盒（含空隙）视为不可通行。以连续地板、脚部和头部两格净空进行BFS，从入口内侧检查客厅、卧室及每件家具旁的接近点；同时核对隔墙和家具方案。
- 这是保守的格子几何校验，不宣称已证明游戏真实角色碰撞、开门、坐卧或交互动作。不会将此专用校验强加给用户导入的雕塑、树屋等任意蓝图。
- 最终仍输出schema3，经既有BuildPlanner/BuildTask/撤销/回滚，10000格事务、64轴、32格批次和主机权限不变。清障不会自动挖空未写入的室内格，实际场地仍由预检检查。

[三份示范JSON及参数清单](examples/furnished-homes/README.md)：9×13/621格、11×15/812格、13×17/1190格；数量为结构加展开家具，不含引擎另补的门上半格。

测试工具 `--furnished-homes` 导出真实生成结果和布局清单；`scripts/Render-FurnishedHomes.py` 从实际JSON结构、家具包围盒和地板重建可通行格，核对接近点可达后绘图。图中屋顶隐藏，黄色点表示可达路径，圆圈为家具接近点；不是游戏截图。已查看单图和三图总览并修正文字排版，图片写入忽略的`artifacts/furnished-homes/`。

```powershell
dotnet tests/BuilderAssistant.Tests/bin/Release/net8.0/BuilderAssistant.Tests.dll --furnished-homes docs/examples/furnished-homes
python scripts/Render-FurnishedHomes.py
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/Build-NetMod.ps1 -GameDir <本机SCNET目录>
```

绘图依赖Pillow和中文字体（`--font`可指定）；本机使用已安装SDK，net8离线测试由.NET9运行（`DOTNET_ROLL_FORWARD=Major`）。
