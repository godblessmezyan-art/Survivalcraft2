# Survivalcraft Ruins 生存战争·遗迹

> SCNET x25.01.17 专项移植说明：本目录固定引用真实
> `Survivalcraft.exe`/`Engine.dll`/`EntitySystem.dll`，生成 `.NET Framework 4.7.2`
> 的 `SurvivalcraftRuins.netmod`。Windows 程序集编译、ABI、85 项测试和包内容校验为
> **已确认**；Android 7723 的加载、世界生成、箱子、守卫与联机同步仍为**待验证**，
> 实机通过前不得宣称兼容。详见仓库根目录 `docs/SCNET-X25-PORT.md`。

Windows 构建：

```powershell
.\SurvivalcraftRuins-Port\scripts\Build-NetMod.ps1 `
  -GameDir 'E:\SCNET\SCNETx25.01.17' -Configuration Release
```

产物、完整日志和 SHA-256 分别写入 `SurvivalcraftRuins-Port/artifacts/` 下的
`SurvivalcraftRuins.netmod`、`SurvivalcraftRuins-build.log` 与
`SurvivalcraftRuins.sha256`。构建脚本不会安装 Mod，也不会访问或修改玩家存档。

为生存战争(SCAPI 1.9.2+)世界生成添加 23 种可探索结构(14 个生成槽位,同槽随机变体)。
沙漠神殿、丛林神庙、海底神殿按 Minecraft 1.16.5 原版生成器的精确布局复刻(尺寸、房间、
机关坐标一一对应),其余参考 YUNG's Better Dungeons 与 When Dungeons Arise 的布局思路。
方块与数值全部为 SC 原生内容。

机制要点:

- **确定性生成**:同一世界种子永远生成同样的结构布局(seed+网格坐标哈希),
  跨区块结构分片写入,互不依赖生成顺序。
- **生物群系限定**:生存战争没有"群系"这种对象,地形只由温度、湿度两张噪声图
  (各 0~15)驱动——草色、树种、雪线、动物分布全看它俩。三座神殿就用游戏自己的
  `CalculateTemperature`/`CalculateHumidity` 取值筛选,湿度≤6 正好是游戏里橡树
  概率为 0 的界(见 `PlantsManager.CalculateTreeProbability`),所以沙漠神殿落点
  一定在无树的干热地带。
- **格内选址重试**:每个格子仍然只有一个候选,但会在格内按确定性顺序试最多 8 个
  落点,第一个同时满足群系、坡度、水深的点胜出。0.5 版每格只试一个点,导致真实
  世界里绝大多数候选被"这一点恰好是海/是坡"否掉——实测一张真实地图,按 40 个/km²
  调的表实际只落地 19.7 个/km²,沙漠神殿更是 **36 km² 内只有 0~1 座**(所以找不到)。
  重试之后表上的数值才等于实际密度。
- **间距控制**:同槽位实例只在格子中央 50% 内抖动,天然留出至少四分之一格间隔;
  跨槽位按保持距离(小结构 40 格、大地标 150 格)互相排斥。陆地结构约 20 个/km²,
  平均最近邻约 110 格;其中**无害小建筑单独约 5~7 个/km²、平均 200 格一座**,
  大型/危险结构更稀疏(斗兽场/天空堡垒约 1.3 个/km²)。
- **神殿密度**:实测三张真实地图(种子 36154/19543/92634),36 km² 范围内沙漠神殿
  3~10 座、丛林神庙 9~16 座(0.5 版分别是 0~1 座和 1~3 座)。换算到对应群系内部
  **大约 200 格就有一座,走进沙漠/丛林基本都能撞见**。
- **守卫守在箱子旁**:守卫点默认取宝箱位置(模板自带的埋伏标记只在结构完全没有
  箱子时才用)——早先版本用的是从原结构导入的刷怪点,结果守卫散落在没东西的房间里。
  **两座神殿例外**:那里的箱子就摆在陷阱触发器旁边,守卫在箱子边踱两步就会踩响压力板、
  在玩家到场之前把火药炸掉,所以它们的守卫改在自己声明的岗位上(沙漠=入口大厅、
  丛林=上层主厅),离机关至少隔一层楼。
  守卫总数 = `clamp(箱子数 × 系数 + 基数, 下限, 上限)`,
  再摊到各触发点,而不是每个标记刷一窝——斗兽场因此从最多 24 只狮子收敛到 6~10 只,
  而原本零守卫的天空堡垒补上了 8~12 只精英。小型结构(营地/摊位/神龛/许愿井/渔屋)
  刻意不设守卫,保留"白捡"的探索乐趣。
- **多箱分池战利品**:每结构多个箱子,按位置分配不同加权池(保底池必有收获,
  稀有池经常落空);箱子内容按位置+种子确定性生成。发射器同样会被装填(箭)。
- **一次性触发**:玩家首次接近触发,触发状态持久化在世界目录
  `SurvivalcraftRuins.json`。水生守卫会在水格中生成,不会搁浅在空气里。
- **风化**:废墟类结构按概率塌洞、石砖换圆石,每个实例风化模式不同但可复现。
- 复用官方 `TreasureGeneratorBlock`(许愿井/沉船/海底神殿),挖开相邻方块时按官方权重表吐宝。

## 设置

游戏内模组设置(通过 `SaveSettings`/`LoadSettings` 持久化):

| 项 | 取值 | 说明 |
|---|---|---|
| `Density` | 0~3,默认 1 | 遗迹密度倍率。0.5≈稀疏,2≈接近 0.4 版的密度 |
| `Guards` | 0~3,默认 1 | 守卫数量倍率。0 = 完全关闭守卫 |

两项设置随时生效,不再"首次进入时冻结"。

## 装进老世界

**可以直接装进已经在玩的存档,不用开新档。** 结构只写进**新生成的区块**,已探索的
地形一格都不动,不会碰你已有的建筑;继续往外跑,新地方就会开始出现遗迹。

0.7 之前会把世界钉在它创建时的布局表上(为了防止已探索边界上出现半截建筑),结果是
老世界永远拿不到新内容。现在取消了:**所有世界一律用当前布局表**。代价很小——只有在
已生成土地的边界上、且新旧布局恰好不一致的地方,可能出现一处写了一半的建筑。

## 安装

同一份源码,**分别针对两个运行时编译**出两种包:

- **插件版(SCAPI 1.9.2+)**:`SurvivalcraftRuins.scmod` → 游戏 `Mods` 目录
- **联机版(SurvivalcraftNet 2.4)**:`SurvivalcraftRuins.netmod` → 游戏 `NetMods` 目录

包名不带版本号:升级时直接覆盖同名文件即可,不会出现新旧两份同时被加载的情况。
版本号写在 `modinfo.json` 里,游戏的模组列表和 Release 页都能看到。

注意两个包的 DLL **不可互换**:SCAPI 的 `ModsManager` 在全局命名空间,Net2.4 的在
`Game` 命名空间,二进制引用在编译时定死,装错版本会报
`TypeLoadException: Could not load type 'Game.ModsManager'`。源码层面无单端专有
依赖(`CommonLib.WorkType` 反射探测、JSON 用 .NET 内置 System.Text.Json)。

联机行为:结构生成、箱子填充、埋伏触发全部只在主机端执行(客户端通过区块/实体
同步获得结果),埋伏与待填箱子状态持久化在主机的世界目录中。

仅在新生成的区块中出现结构;已探索区域不受影响。删除模组后已生成的结构保留
(纯原版方块,无残留依赖)。

## 开发

```bash
dotnet build src/SurvivalcraftRuins            # 需要 ~/sc-libs 下的游戏 DLL
dotnet test tests/SurvivalcraftRuins.Tests     # 纯逻辑测试,不依赖游戏运行时
tools/package.sh                               # 产出 artifacts/*.scmod
```

模板转换器(MC 结构 .nbt → SC 模板 JSON):

```bash
python3 tools/convert_nbt.py <in.nbt> <out.json> <name> [--sink=N]
```

MC 方块按映射表降采样到 SC 调色板;箱子/木桶→箱子标记,刷怪笼→埋伏标记,
门/蛛网/告示牌等无对应物→空气(废墟风格正好留门洞)。

## 陷阱电路

三座机关(丛林神庙两处射箭陷阱、沙漠神殿的火药密室)不再靠"方块放对了就应该能通"
的推断:`tests/…/ElectricModel.cs` 把游戏 `SubsystemElectricity` 的接线规则整套搬了
过来——120 项连接路径表、36 项接口方向表、各方块的 `GetConnectorType`、以及电线同格
合并规则,`TrapTests` 据此断言"压力板与发射器属于同一条电路"。

0.5 版三处电路**全部是断的**:每个元件各自成一个连通分量(电线离压力板隔了两格、
起爆器挂载面朝 +Z 而信号从正上方来)。0.6.1 重新布线并加了回归测试:

- 压力板 → 地面电线 → 嵌在走廊尽头墙里的发射器(平射,箭矢沿走廊飞)。
- 沙漠神殿:压力板 →(正下方)穿石电线 → 起爆器(挂载面 5,吊在电线块下面)→
  周围 8 桶中号火药。爆炸半径约 0.13·√360 ≈ 2.5 格/桶,足够把密室和 4 个箱子一起送走。
- 丛林神庙三拉杆(**活塞是干什么的**):走廊尽头一侧是三根拉杆,正对面墙上是一块
  带过梁的石砖门板——门板后面就是藏第二个箱子的壁龛。拉对那根杆,墙里的两台黏性活塞
  把门板横推进旁边的凹槽,门就开了;拉错那根会从背后的发射器射你一箭;第三根什么也
  不做。门板是普通石砖,**万一活塞在游戏里不按预期动作,直接挖开就行**,战利品不会锁死。

## 已知待游戏内验证项

- 活塞推拉:SC 的活塞把塞块推进凹槽这一步只做了几何验证(伸长上限设为 1 格,
  凹槽留空),实际推动行为仍需进游戏确认。
- 楼梯/梯子/火把的朝向 data 位按源码推断,转换结构里个别朝向可能不对(纯视觉)。
- 灯塔顶部矿灯照明范围、营火是否会熄灭(纯视觉)。
- 海底神殿:深海生成频率、下潜氧气压力是否合适、鲨鱼守卫的寻路表现。
- 联机版需实测:非主机客户端进入结构区域、开箱、触发守卫后的同步表现。
